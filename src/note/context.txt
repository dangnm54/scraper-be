Project Goals
You are building an automated web scraper for Airbnb to perform live market research. The core purpose is to collect publicly available data and display it on a dashboard. Your long-term goal is to build a program on top of other AI models, but the immediate focus is on scraping and data analysis.

Project Roadmap
The project follows a phased approach:

Python Foundations: Completed. You have a solid grasp of Python, Pandas, and basic data visualization.

Web Scraping: Current focus. You are learning to use Selenium for controlling a web browser like a human, and BeautifulSoup for parsing web page structures. This phase will cover handling pagination, proxy servers, and robust error handling.

Web Application Development: This will follow the scraping phase. Your goal is to build a web-based user interface using React, Shadcn/ui, and Lucide icons to interact with the Python backend.

AI Integration: This is a later phase, after the core scraping and data handling are complete.

Technical Implementation
The project is split into two main parts: a backend (scraper-be) and a frontend (scraper-fe).

The backend is the "engine" written in Python with FastAPI, responsible for the scraping logic and saving data to a database. It uses Selenium to navigate the Airbnb website and BeautifulSoup to extract data. It will also use proxies to avoid detection.

The frontend is the user interface, built with React and TypeScript, styled with Tailwind CSS. It communicates with the backend via API calls to trigger scraping and display the results.

Specific Scraping Goals
Scrape a list of properties: Use search filters to find properties and collect key details like title, price, rating, and the link to the property detail page.

The project is being developed using an MVP (Minimum Viable Product) approach. This means the immediate goal is to launch the simplest, most basic version of the app to get user feedback as quickly as possible. To achieve this, several features are being intentionally excluded from the initial release:

Authentication: The MVP will not have a user login system or a secure API. The focus is on functionality, not security.

Complex Deployment: The project will use a lean deployment strategy with Railway for the backend and Vercel for the frontend to get the app live quickly, without the need for manual configuration or complex DevOps.

This adjusted, lean roadmap prioritizes getting a working product to market faster.

project has a clear and logical structure with two main directories: scraper-be for your backend and scraper-fe for your frontend.

Project Structure
scraper-be: This folder contains all the code for your Python FastAPI backend. It's the "engine" that handles the web scraping logic, data processing, and communication with your database.

scraper-fe: This folder contains all the code for your React frontend. It's the user interface that runs in a web browser, allowing users to interact with your backend.



########################## Backend Summary
1. Core Language and Framework
Language: Python
Framework: FastAPI (for API server)
2. Key Dependencies (from requirements.txt)
Web Scraping: selenium, beautifulsoup4, lxml, requests
Data Handling: pandas, numpy, openpyxl
Visualization: seaborn, matplotlib
API & Web: fastapi[all], uvicorn, pydantic
Database: sqlalchemy, psycopg2-binary
Other: screeninfo, tqdm, python-logging-loki, python-dotenv
3. Database Technology
ORM: SQLAlchemy
Database: PostgreSQL (via psycopg2-binary)
Connection: Configured via DATABASE_URL in a .env file (see scraper/tool/db_op.py)
Model Example: PropertyDB (see scraper/type/data.py) represents a properties table.
4. Major API Endpoints (from main.py)
Endpoint	Method	Purpose
/	GET	Health check; confirms backend is running.
/api/run	POST	Triggers the main scraping process. Receives settings, returns status.
/api/data/file-list	GET	Returns a list of all scraped files (metadata) from the database.
/api/data/file-detail/{file_id}	GET	Returns detailed data for a specific file by its ID.
/api/data/file-download/{file_id}	GET	Downloads the file data for a given file ID.
5. Core Logic Location and Purpose
Web Scraping Logic:
Located in scraper/base.py and scraper/detail_step/ (e.g., scrape_p1.py, scrape_p2.py, browser.py).
run_full_flow in scraper/base.py orchestrates the scraping process.
Uses Selenium for browser automation and BeautifulSoup/lxml for HTML parsing.
Data is processed and saved to the database via SQLAlchemy models.
Supporting Modules:
scraper/tool/: Utility modules for file/database operations, logging, config, etc.
scraper/type/: Pydantic models and SQLAlchemy ORM models for data validation and DB schema.
In summary:
This repo is a Python FastAPI backend for orchestrating and managing web scraping jobs, storing results in a PostgreSQL database, and exposing endpoints for triggering scrapes and retrieving results. The core scraping logic is modularized under scraper/, with clear separation between scraping steps, data models, and utility functions.


########################## Frontend Summary
1. Core Language and Framework
Language: TypeScript (with some files in JSX/TSX)
Framework: React (see src/App.tsx, src/main.jsx, and package.json dependencies)
Build Tool: Vite (see vite.config.js, package.json scripts, and README.md)
2. Key UI Libraries Used
Shadcn/ui: Used for component structure and design (see components.json and src/components/ui/)
Tailwind CSS: Main styling framework (see src/index.css, tailwindcss in package.json, and components.json)
Radix UI: For accessible UI primitives (see dependencies like @radix-ui/react-checkbox, @radix-ui/react-dialog, etc.)
Lucide-react: Icon library (see lucide-react in package.json and components.json)
Other utilities:
class-variance-authority, clsx, tailwind-merge for class management
tw-animate-css, tailwind-scrollbar for additional styling
3. How the Frontend Interacts with Backend APIs
API Client: Located in src/lib/api-client.ts
Uses fetch to communicate with a backend at http://127.0.0.1:8000
Provides functions like apiClient_JSON and apiClient_Download for GET/POST and file download
Handles network, HTTP, and application errors robustly
Usage in Components:
Example: src/components/main/form-tab/config-form.tsx uses apiClient_JSON to POST form data to /api/run
Example: src/components/main/side-bar.tsx fetches file lists from /api/data/file-list
SSE (Server-Sent Events): src/components/main/form-tab/sse-log.tsx connects to http://127.0.0.1:8000/sse/logs for real-time log updates
4. Location of Main UI Components
Main App Entrypoint: src/App.tsx
Renders the main layout, sidebar, and main content area
Component Structure:
src/components/main/
side-bar.tsx – Sidebar navigation and file selection
form-tab/ – Contains config-form.tsx (form for scraper config), run-page.tsx (main run interface), sse-log.tsx (real-time logs)
data-tab/ – Contains data-content.tsx, data-page.tsx (data display)
src/components/ui/ – Reusable UI primitives (button, card, input, label, etc.), mostly styled with Tailwind and Shadcn/ui conventions

Phase 4: Lean Deployment & Integration
This adjusted plan combines the deployment tasks into a single, focused two-week effort. It removes the over-scoped authentication steps to get your app live faster.

Week 15: Backend Deployment & Integration
Finalize Backend APIs. Make sure your FastAPI backend has the necessary endpoints to trigger scraping and retrieve data from your Supabase database.

Set up the project on Railway. Create a new Railway project and connect it to your GitHub repository.

Configure your environment variables. Add your Supabase connection URL and any other secrets to Railway. Railway will automatically deploy your backend.

Test the live API. Use a tool like Postman to ensure your new, live API endpoints are working correctly.

Week 16: Frontend Deployment & Linking
Prepare the React app for deployment. In your package.json file, adjust your scripts and build settings as needed.

Set up the project on Vercel. Create a new Vercel project and connect it to your React app's GitHub repository.

Link the frontend to the backend. Add a new environment variable in Vercel that holds the URL of your live Railway backend. Your React code will use this variable to make API calls.

Deploy and test. Vercel will automatically build and deploy your React app. Test the entire flow from your browser to ensure the frontend can trigger the scraper and display the results.

This lean roadmap gets your app live for testing and feedback in two weeks instead of five, prioritizing action over unnecessary features for your MVP.




"Installing a headless browser and its driver on the Railway server": This is the perfect lean approach. You package the browser and driver directly with your application inside a headless container. Railway runs this container, so your app has everything it needs. This is self-contained, simple to manage, and has no extra cost.
